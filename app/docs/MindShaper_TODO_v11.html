Sprawdzenie i ew. naprawa

Istotny Domyślne ikony domen — spec mówi „domyślne nazwy i ikony", seed nie ustawia ikony.
  • seed daje DomainEntity(assetsIconId = null) — 10 domyślnych domen startuje bez ikony
  • mapper mapuje assetsIconId: Int? → iconId: Int (non-null), więc null jest unboxowany do prymitywu
  • skutek na UI: albo domeny pokazują pustą ikonę ic_domain_none (fallback dla id 0), albo — mniej prawdopodobne — crash przy pierwszym starcie (NPE z unboxingu)
  • do sprawdzenia na urządzeniu: wyczyść dane, wejdź w Ustawienia → jaka ikona przy domenach; pusta „none" = wariant 0, crash = wariant NPE
  • fix: seed powinien nadać domyślną ikonę zamiast null — spełnia spec i usuwa ryzyko null → Int
Gdzie
  • database/initialization/DatabaseInitializer.kt — seedDomains(), DomainEntity(name = ..., assetsIconId = null)
  • services/mappers/DomainMapper.kt — assetsIconId → iconId
  • services/dto/DomainDTO.kt — iconId: Int (non-null)
  • services/DomainIconsService.kt — getIconResourceId, fallback ic_domain_none
Krytyczny Wynik createSnapshot() ignorowany na starcie — cichy błąd zapisu backupu.
  • createSnapshot() zwraca Result<File>, ale wywołanie na starcie apki nie sprawdza wyniku
  • skutek: jeśli zapis się wywali (brak miejsca, cofnięte uprawnienie, błąd IO), użytkownik jest przekonany, że ma backup, a pliku nie ma
  • do rozważenia: log/telemetria przy porażce, albo odzwierciedlenie stanu w metadanych sekcji
Gdzie
  • ApplicationMain.kt — if (isBackupEnabled()) snapshotManager.createSnapshot() (wynik nieużyty)
  • database/initialization/DataSnapshotManager.kt — createSnapshot(): Result<File>
Istotny checkAndRequestPermissions w środku restoreSnapshot — może przerwać wczytywanie.
  • na Androidzie 11+ metoda robi startActivity do ustawień systemowych, gdy brak uprawnienia — wywoływana na początku restoreSnapshot
  • skutek: jeśli uprawnienia brak, restore nie tyle prosi i czeka, co wyrzuca użytkownika do ustawień w trakcie operacji; sam odczyt pliku i tak potem poleci (albo rzuci wyjątek)
  • do sprawdzenia na urządzeniu: wczytanie backupu przy cofniętym uprawnieniu — czy flow jest zrozumiały, czy restore realnie się wykonuje po powrocie z ustawień
Gdzie
  • database/initialization/DataSnapshotManager.kt — restoreSnapshot() woła checkAndRequestPermissions(context) na starcie; checkAndRequestPermissions robi startActivity dla MANAGE_APP_ALL_FILES_ACCESS
