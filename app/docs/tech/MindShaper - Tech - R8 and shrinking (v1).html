Tech: R8, ProGuard rules i keep.xml

Co build release wycina z aplikacji i jak chronimy rzeczy szukane po nazwie. Dokument opisuje stan zaimplementowany; ryzyka oznaczone jako „do sprawdzenia”.

Kontekst

Build release przechodzi przez optymalizację: APK jest mniejszy, a kod trudniejszy do odczytania po dekompilacji. Narzędzie analizuje, co jest używane, startując od punktów wejścia (activity, serwisy z manifestu), i usuwa resztę.

  • Analiza jest statyczna — widzi wywołania w kodzie, nie widzi odwołań budowanych w czasie działania: refleksji, nazw zasobów składanych z tekstu, kluczy JSON czytanych z nazw pól.
  • Reguły keep to sposób, by powiedzieć narzędziu „to jest używane, choć tego nie widzisz”.
  • ProGuard a R8 — R8 zastąpił ProGuarda w Android Gradle Plugin, ale czyta te same reguły; stąd nazwa pliku proguard-rules.pro.
  • Objaw — debug działa, release nie: pusta lista, brak pliku, crash z nazwami a.b.c w stack trace.

Dwa niezależne mechanizmy

  • Tylko release. W buildTypes.release oba przełączniki są włączone; debug niczego nie wycina — dlatego problemy wychodzą dopiero na buildzie release.
  • Reguły bazowe — proguard-android-optimize.txt z AGP plus nasze proguard-rules.pro; biblioteki (Room, Hilt) dokładają własne reguły automatycznie.
  • Osobne światy. Reguła w proguard-rules.pro chroni pole klasy, ale nie plik zasobu — i odwrotnie. Rzecz szukana po nazwie zwykle potrzebuje obu.

Wzorzec „szukane po prefiksie”

Zasób, do którego kod nie odwołuje się przez R.raw.x / R.drawable.x, tylko przegląda pola klasy R refleksją i filtruje po prefiksie nazwy.

  • Zaleta — nowy plik z prefiksem pojawia się w aplikacji bez zmiany kodu.
  • Koszt — dla R8 pola R są nieużywane, więc je usuwa; refleksja w release zwraca pustą listę.
  • Koszt — shrinker nie widzi odwołania do pliku, więc może go usunąć z APK.

Bank fiszek — chroniony

  • Pliki res/raw/flashcards_bank_*.txt; FlashcardsBank przegląda R.raw::class.java.fields po prefiksie flashcards_bank_.
  • Pola — -keepclassmembers class pl.hexmind.mindshaper.R$raw { public static <fields>; } w proguard-rules.pro.
    • zachowuje wszystkie pola R.raw (także paths_seed) — koszt pomijalny
  • Pliki — tools:keep="@raw/flashcards_bank_*" w res/raw/keep.xml; gwiazdka działa jak prefiks, więc nowe pliki banku są chronione bez edycji.
  • keep.xml sam nie trafia do APK — shrinker czyta go przy buildzie i usuwa.

Ikony domen — do sprawdzenia

  • Ten sam wzorzec — DatabaseInitializer.createIconsList() przegląda R.drawable::class.java.fields po prefiksie z_ic_domain; galeria ikon dostaje to, co znajdzie.
  • Brak reguły dla R$drawable — w release lista ikon może wyjść pusta.
  • Pliki prawdopodobnie przeżywają — DomainIconsService woła getIdentifier(), a wtedy shrinker (tryb safe) zachowuje zasoby pasujące do stałych tekstowych w kodzie, także prefiksów. Pewniej: dopisać @drawable/z_ic_domain_* do keep.xml.

Gson — do sprawdzenia

  • Gson czyta nazwy pól refleksją. R8 skraca nazwy, więc bez reguł JSON w release ma klucze a, b… zamiast title.
  • Backup — DataSnapshotManager zapisuje encje Room (ThoughtEntity itd.) bez @SerializedName.
    • ryzyko: backup z release nieczytelny dla debug i dla innej wersji release (nazwy mogą się zmienić między buildami)
  • Seed ścieżek — PathSeedEntry ma @SerializedName, więc nazwy są bezpieczne; zostaje TypeToken — R8 w trybie pełnym (domyślny od AGP 8) może usunąć informację o typie generycznym. Błąd jest łapany, więc skutkiem byłby brak ścieżek startowych, nie crash.
  • Gson 2.10.1 nie ma wbudowanych reguł R8 (pojawiły się w 2.11).
  • Zadanie jest w TODO.

Jak sprawdzić

  • Build release na urządzeniu — import fiszek: zakładka „Z banku” z pigułkami; galeria ikon domen; backup → restore; ścieżki startowe na czystej instalacji.
  • Raporty R8 — app/build/outputs/mapping/<wariant>/: usage.txt (co usunięto), mapping.txt (stare → nowe nazwy), resources.txt (decyzje shrinkera).

Pułapki — nie ruszać

  • Zmiana prefiksu (flashcards_bank_) — trzeba poprawić stałą w FlashcardsBank i wzorzec w keep.xml razem.
  • Nazwy w res/ — tylko małe litery, cyfry i _; „Apteka.txt” wywala build.
  • R$raw z dolarem — klasa zagnieżdżona; zapis R.raw w regule nic nie chroni.
